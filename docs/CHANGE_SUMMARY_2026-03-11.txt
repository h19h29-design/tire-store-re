Tire Store 변경 요약
작성일: 2026-03-11

1. 이번에 추가 반영한 내용
- 빠른판매 금액 입력을 천원 단위 기준으로 다시 정리했다.
- 얼라이먼트 금액을 빠른판매에서 별도 입력받고 service line / work log로 저장되게 맞췄다.
- 저재고 임계값 설정 키를 inventory / dashboard / settings에서 공용으로 쓰도록 통합했다.
- 판매 입력 오류, 재고 입력 오류, 대시보드 입력 오류, 설정/백업 오류, import 오류를 팝업으로 바로 보여주도록 추가했다.
- Rust 샘플 파일 테스트가 특정 PC 다운로드 경로에 고정 의존하지 않도록 정리했다.

2. 기존과 달라진 점
[기존]
- 빠른판매 금액이 화면상 천원 단위 요구와 다르게 실제 원 단위처럼 처리되는 구간이 남아 있었다.
- 얼라이먼트는 고객 화면 집계는 있었지만 빠른판매에서 별도 구조화 저장이 안 됐다.
- 저재고 임계값이 어떤 화면은 inventory.lowStockThreshold, 어떤 화면은 dashboard.lowStockThreshold를 봐서 값이 어긋날 수 있었다.
- 입력이 잘못돼도 상태 문구만 바뀌고 저장 버튼을 누른 뒤 사용자가 놓치기 쉬웠다.
- 대시보드 저장이나 import 실패도 상태 문구 위주라 즉시 원인 파악이 어려웠다.
- Rust 테스트 일부는 로컬 Downloads 샘플 파일 전제가 강했다.

[변경 후]
- 빠른판매 단가, 얼라이먼트, 추가 작업비, 카드, 현금 입력을 천원 단위로 넣으면 원 단위로 환산 저장된다.
- 얼라이먼트 금액은 별도 service entry로 저장되고 고객/차량 집계에도 반영된다.
- 저재고 임계값은 공용 설정 로더/세이버를 통해 같은 값으로 동작한다.
- 저장 전 검증에서 잘못된 항목을 팝업 목록으로 보여주고 저장을 막는다.
- 저장 중 예외도 팝업으로 즉시 표시한다.
- 대시보드 지출 저장, 저재고 기준 저장, 초기 import 실패도 팝업으로 즉시 표시한다.
- Rust 테스트는 샘플 파일이 없으면 건너뛰고, 있으면 실제 검증을 수행한다.

3. 팝업 검증 대상
- 판매 합계가 0원인 경우
- 판매표에 수량 0 또는 단가 0 항목이 있는 경우
- 추가 작업명만 있고 추가 작업비가 0원인 경우
- 카드+현금 합계가 총합계와 다를 경우
- 재고 입력 시 상품 미선택
- 재고 입력 시 수량 0 이하
- 기본 백업 폴더 미선택 상태에서 즉시 백업 실행
- 지출 날짜/지출 금액/저재고 기준 입력 오류
- import 파일 미선택
- 저장/백업/재고 반영/대시보드 저장/import 중 발생한 예외

4. 테스트 결과
- npm run lint: 통과
- npm run build: 통과
- cargo test: 통과

5. 아직 남아 있는 리스크
- 대시보드 순이익의 타이어 원가는 판매 시점 snapshot이 아니라 현재 items.default_cost_price 기준이다.
- 과거 데이터의 얼라이먼트 집계는 여전히 work_type / memo 키워드 추정이 일부 포함된다.
- 카드/현금 불일치는 이제 저장 전 차단하지만, 추후에는 자동 분배/자동 보정 UX를 붙일 여지가 있다.

6. 다음 작업 제안
- 판매 시점 원가 snapshot 컬럼 도입
- 팝업뿐 아니라 잘못된 입력 칸 테두리 강조 추가
- 고객/차량 상세 보기 또는 수정 팝업 추가
- 대시보드 검증 결과 export 기능 추가
