# Phase 2 Detailed Work Plan

## 목표

현재 MVP를 실제 매장 운영 수준으로 끌어올립니다.

## 요구사항 묶음

### A. 데이터 정확도 / import

- 금액 입력은 천원 단위
- 일자별 판매량 불일치 점검
- 규격 띄어쓰기 정규화
- 고객등록 시트 및 판매 관련 이력 import 확장

### B. 판매 / 재고

- 얼라이먼트 금액 기본 입력란
- 추가작업 미입력 저장 허용
- 상품검색 토큰 개선
- 재고조회에서 판매가 제거

### C. 고객 / 차량

- 차량번호 중심 화면
- 판매건수 대신 판매수량
- 비고, 판매금액, 결제구분, 얼라이먼트 금액 표시
- 키로수 입력란 추가

### D. 대시보드 / 운영

- 일일 수익 표시
- 일일 지출 입력 및 반영
- 총 재고 수량 표시
- 저재고 경고 및 설정
- 날짜/월/연도별 분석 정합성 확보

## 구현 순서

1. 금액/규격/import 정확도
2. 판매 저장 구조 확장
3. 고객/차량 화면 재구성
4. 대시보드 집계 재검증
5. 설정/옵션 연결

## 기본 가정

- 금액 저장 단위는 `원`
- 입력 UI만 `천원 단위`
- 기본 저재고 임계값은 `4개`
- 규격 표시 표준은 `숫자 숫자 숫자` 공백 구분
- 순이익 계산식은 `타이어 매출 - 타이어 원가 + 정비/얼라이먼트 수익 - 일일지출`
- `타이어가격`은 우선 재고 기준 `원가`로 해석

## 꼭 확인이 필요한 부분

- 고객명은 숨기지 않고 유지하되, 목록과 검색의 중심은 차량번호로 구성
